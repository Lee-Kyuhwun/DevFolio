# ADR: 근거 기반 성과 확정 (정성 효과 Hard Gate)

- 상태: Accepted
- 날짜: 2026-11-16
- 결정자: ImpactNote AI 파이프라인 작업
- 관련: `impactnote/core/claims.py`, `metrics.py`, `ai.py`, `intel/ai_stage.py`,
  `report.py`, `evals/impact/gate.py`, `evals/impact/live_ab.py`

## Context

2026-11-15 평가에서 Historical 생성문의 Combined Hallucination Rate 는 47.6%
(20/42, 95% CI 33.3–61.9%)였고, 사실성은 2.65/5였다. 숫자 가드레일을 강화한 뒤
저장된 근거 없는 숫자는 표본에서 0%였지만, "안정성 향상", "비용 절감" 같은 정성
효과 주장은 검증 없이 저장·보고서에 남았다.

42개 claim 을 다시 분류하면 unsupported/contradicted 20개 중 12개가 정성 효과
주장이다. 수치만 막아서는 절반 이상을 막을 수 없다.

## Problem

1. AI가 `result`/`statements`에 근거 없는 효과를 자유롭게 쓴다.
2. 숫자가 없는 효과 문장은 `sanitize_claims`를 통과한다.
3. 사용자가 AI 후보를 "확인"하면 보고서가 그 문장을 그대로 싣는다.
4. 프로젝트 분석 후보도 `result`의 효과 주장을 검증하지 않는다.
5. "80%"가 근거의 "80ms"로 통과하는 단위 무시 결함이 있다.

## Considered Alternatives

| 대안 | 내용 | 왜 채택/기각했는가 |
| --- | --- | --- |
| A. Hybrid Retrieval + Rerank | BM25·심볼·임베딩·리랭킹 | 42개 중 12개는 이미 문맥에 근거가 있어도 생긴 효과 주장이다. 검색만으로 막히지 않으며 인덱스 운영 비용이 든다. 보류. |
| B. 구조화 Claim 스키마 | `claims[]` + `evidence_quote` 강제 | 검증 가능성은 높지만 JSON 절단·소비자 전면 수정 위험이 있다. 프롬프트 규칙과 Gate로 부분 채택. |
| C. Atomic Claim + NLI/Judge | claim 단위 독립 심사 | 의미 반대를 잡을 수 있으나 호출 비용·지연·Judge 오탐 평가가 선행돼야 한다. 이번 라운드 보류. |
| D. 결정론 효과 Gate | 효과 문장 추출 + 근거 대조 + 삭제 | 비용 0, <1ms, 재현 가능. 22개 효과 claim 중 12개 차단·10개 보존. **채택.** |
| E. Generate → Critique → Repair | 생성 후 비평·수정 반복 | 새 주장을 만들 위험과 호출 비용이 크다. 기각. |
| F. 전체 보류 | 근거 부족 시 모든 결과 거절 | 환각률은 낮아지지만 유용한 결과 제공률이 0이 될 수 있다. 문장 단위 보류로 부분 채택. |
| G. NeMo Guardrails | fact-checking rail 도입 | 별도 런타임·설정이 필요하고 한국어 효과 판정 품질을 측정하지 않았다. 보류. |
| H. NeMo Retriever | 임베딩·리랭킹 시스템 | 활동 1건 분석에는 과하다. 보류. |

## Decision

1. `impactnote/core/claims.py` 에 **결정론적 효과 주장 Gate** 를 추가한다.
   - 효과 술어(향상·개선·절감·단축·보장·예방·제거·분산 등)를 문장 단위로 찾는다.
   - 근거 문장에 같은 대상과 같은 효과 표현이 있거나, 수치+단위가 일치할 때만
     SUPPORTED 로 본다.
   - "측정되지 않음/기록 없음"은 명시적 UNSUPPORTED 다.
   - 효과 주장이 아니면 건드리지 않는다(구현·설계 사실은 유지).
2. AI 저장 경로(`ai.py`)에서 수치 가드레일 **후** 효과 Gate 를 적용하고,
   차단 내역을 `unverified_effects` 에 남긴다.
3. 프로젝트 분석(`intel/ai_stage.py`)의 finding/candidate 문장에도 적용하고,
   차단 시 품질을 HYPOTHESIS 로 낮춘다.
4. 보고서(`report.py`)는 `source in {ai, analysis, git}` 성과에 대해 확인 후에도
   외부 근거로 효과 주장을 재검증한다. 사용자가 직접 쓴 성과에는 적용하지 않는다.
5. 수치 검증을 **값 + 정규화 단위** 로 강화한다(`80%` ≠ `80ms`, `10m` = `10분`).
6. 프롬프트에 효과 주장 조건을 명시한다(측정값·전후 비교가 있을 때만).
7. 평가 하네스에 `effect_gate` 지표와 `--live` ablation 을 추가한다.

## Decision Rationale

- 직접 원인이 검증 실패(F)와 보고서 재유입(G)이므로, 생성 모델을 바꾸지 않고
  저장·보고서 직전에 결정론적으로 막는 것이 가장 작은 변경이다.
- 12개 표적을 모두 차단하면서 근거 있는 10개를 모두 보존했다. Recall 손실이
  측정되지 않았다.
- 새 의존성·서비스·유료 호출이 없다. 오프라인·Docker·CI 에서 동일하게 동작한다.
- Judge·Retriever 없이도 측정 가능한 개선을 만들고, 남은 한계를 명시할 수 있다.

## Consequences

긍정:

- 근거 없는 정성 효과가 AI 저장 결과와 기계 생성 성과 보고서에 남지 않는다.
- 차단 사유가 사용자에게 보인다(`unverified_effects`, "확인 필요 항목").
- 평가에서 false accept 0/12, retention 10/10 을 재현할 수 있다.
- 숫자 단위 혼동(80% vs 80ms)이 차단된다.

부정/비용:

- 한국어 효과 표현 규칙을 유지해야 한다. 새 표현은 누락될 수 있다.
- 근거가 있지만 표현이 다른 효과 주장은 차단될 수 있다(보수적).
- 의미 반대(c034, c037), 기능 존재(c005, c024, c038), 기여 귀속은 여전히 못 잡는다.
- Judge 비용을 쓰지 않으므로 의미 기반 판정은 없다.

데이터 영향:

- 기존 저장 데이터는 삭제·변경하지 않는다. 보고서 생성 시점에만 재검증한다.
- 새 AI 분석 결과에는 `unverified_effects` 키가 추가된다(하위 호환: 추가 필드).
- `sanitize_claims` 의 단위 대조가 엄격해져, 단위가 다른 수치는 `[확인 필요]`가 된다.

## Risks

| 위험 | 완화 |
| --- | --- |
| 평가셋 과적합 | 데이터셋 ID를 코드에 넣지 않고 일반 규칙 사용. 별도 live 3건으로 확인. |
| 근거 있는 주장 차단 | retention 지표와 `false_rejection_ids`를 결과에 기록. |
| 사용자 문장 삭제 | manual 성과에는 Gate 미적용. |
| 규칙 누락 | `unverified_effects`로 차단 내역을 노출하고, 새 표현은 테스트로 추가. |
| 0건 오독 | Wilson 95% 구간을 함께 보고(0/12 → 0–24.3%). |

## Rejected Options

- **NeMo Guardrails 즉시 도입**: 별도 런타임과 한국어 품질 검증이 필요하다.
- **NeMo Retriever 전체 도입**: 현재 활동 단위 분석에 과하다.
- **제품 경로 LLM Judge**: 비용·지연·오탐 캘리브레이션 없이 넣지 않는다.
- **Repair loop**: 검증 실패 시 새 근거를 만들 위험이 있다.
- **모든 AI 결과 보류**: 유용한 결과 제공률을 측정하지 않은 채 Recall을 희생한다.

## Revisit Conditions

다음 중 하나가 확인되면 재검토한다.

1. 새 도메인/문체에서 효과 주장 재현율이 80% 미만으로 측정될 때.
2. retention 이 80% 미만으로 떨어질 때.
3. 의미 반대·기능 존재 오류가 사용자 보고서에 실제로 유입될 때.
4. Judge 비용이 호출당 허용 범위로 내려가고, 한국어 캘리브레이션 데이터가 확보될 때.
5. Guardrails/Retriever 도입으로 42 claim 이상에서 추가 개선이 측정될 때.
