## 사례 1. 운영 비용 절감 (c002)

- 입력: 백오피스 기능 목록.
- AI 주장: "운영 비용을 절감했다."
- 실제 근거: "백오피스 기능 목록만 있고 비용·운영 지표는 기록되지 않음."
- 잘못된 판단: 비용을 언급한 기록이 없다는 사실을 "절감했다"로 일반화.
- 오류 유형: D 생성 + F 검증 실패.
- 수정: 효과 주장 `cost` 로 탐지. 근거 문장에 `비용`이 있으나 `기록되지 않음`
  부정 표현이 있어 지원 문장에서 제외 → 삭제.
- 재평가: 차단. Gold `INSUFFICIENT_EVIDENCE`.

## 사례 2. 개발 생산성 향상 (c003)

- AI 주장: "개발 생산성을 높였다."
- 근거: "생산성 측정값이나 전후 비교가 없음."
- 오류 유형: D/F. 측정 부재를 효과로 바꿈.
- 수정: `productivity` 효과 탐지, `생산성 + 없음` 부정 → 삭제.
- 재평가: 차단. Gold `NEUTRAL`.

## 사례 3. 가용성 위험 (c019)

- AI 주장: "기존 수동 배포는 서비스 가용성에 위험을 초래했다."
- 근거: "수동 배포와 휴먼 에러 기록은 있지만 가용성 영향은 측정되지 않음."
- 잘못된 판단: 기록된 사실(휴먼 에러)에서 기록되지 않은 인과(가용성 위험)를 추론.
- 오류 유형: C 해석 + D 생성.
- 수정: `risk` 효과 탐지, `가용성 + 측정되지 않` 부정 → 삭제.
- 재평가: 차단. Gold `NEUTRAL`.

## 사례 4. 응답 시간 70% 단축 (c031)

- AI 주장: "캐싱을 적용해 응답 시간이 70% 단축되었다."
- 근거: "cache.py에 lru_cache를 추가했다. 성능 벤치마크 결과는 없다."
- 잘못된 판단: 코드 변경(캐시 추가)을 성능 개선으로 확대.
- 오류 유형: D/F.
- 수정: 수치 `70%`가 근거에 없어 수치 가드레일이 `[확인 필요]`로 대체하고,
  효과 Gate 가 나머지 문장을 삭제.
- 재평가: 차단. Gold `NEUTRAL`.

## 사례 5. PostgreSQL 사용 (c034) — 미해결

- AI 주장: "PostgreSQL을 데이터베이스로 사용한다."
- 근거: "설정 파일과 코드는 SQLite만 사용한다."
- 잘못된 판단: 기록과 반대되는 사실.
- 오류 유형: C 해석 + F 검증.
- 수정: 없음. 결정론 효과 Gate 는 효과 주장이 아니므로 통과한다. 숫자도 없다.
- 재평가: **여전히 통과**. 의미 반대 검증(NLI/Judge)이 필요하다.
- 다음 조치: 인용 근거의 엔티티(DB 종류) 대조 규칙 또는 독립 Judge.

## 사례 6. rate limit 100 rpm (c037) — 미해결

- AI 주장: "API rate limit을 100 rpm으로 설정했다."
- 근거: "config.py의 RATE_LIMIT 값은 50 rpm이다."
- 오류 유형: C/F. 값이 다르지만 단위 `rpm` 이 `_CLAIM_PATTERN` 에 없어 수치
  가드레일도 통과했다.
- 수정: 없음. `rpm` 을 수치 단위에 추가하는 것만으로는 "100 vs 50" 모순을
  차단하지 못한다(값이 다르면 `[확인 필요]`가 되지만, 주장 자체는 남는다).
- 재평가: **여전히 통과**. 별도 엔티티/설정 대조가 필요하다.

## 사례 7. 1인 팀 (c001) — 미해결

- AI 주장: "백엔드와 인프라를 1인 팀으로 설계·구축했습니다."
- 근거: "role=백엔드 개발 및 인프라 구축, team_size=4."
- 오류 유형: E 귀속.
- 수정: 없음. 활동 분석 경로에는 팀 규모 필드가 없다.
- 재평가: **여전히 통과**. Git author/co-author 및 프로젝트 메타데이터 대조 필요.

## 사례 8. 80% vs 80ms — 실제 호출에서 발견

- 입력: Redis 캐시 활동 (`result`: "p95 응답 시간 200ms → 80ms").
- AI 주장: "Redis 캐시 도입으로 응답 시간을 80% 이상 단축했습니다."
- 근거: `200ms → 80ms` (80은 ms 값).
- 잘못된 판단: 80ms 의 숫자 80을 80%로 재사용.
- 오류 유형: F 검증 — 값만 비교하고 단위를 비교하지 않음.
- 수정: `_CLAIM_PATTERN` 에 단위를 포함하고 `(값, 정규화 단위)` 쌍으로 대조.
  `%`와 `ms`는 다르므로 차단. `10m`과 `10분`은 같은 단위로 정규화.
- 재평가:
  - `tests/test_claims.py::test_percent_claim_is_not_supported_by_millisecond_value`
    통과.
  - 같은 문장을 효과 Gate 에 넣으면 수치가 없어져 효과 문장이 삭제된다.
- 남은 위험: `80%`를 `80ms`에서 파생하는 것과 같은 **단위 변환 오류**는 잡지만,
  `50%`를 근거의 `50건`에서 파생하는 것도 같은 규칙으로 잡는다. 반대로 근거에
  실제 `50%`가 있으면 통과한다.
