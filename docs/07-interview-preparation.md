# 면접 준비 — 성과노트(ImpactNote)

기준일: 2026-11-15 (최신 AI 검증 Q&A는 [`portfolio/README.md`](portfolio/README.md) §7)

표기:
- **[사실]** 코드·테스트·실행으로 검증 가능
- **[답변 예시]** 본인 경험에 맞게 수정이 필요한 서술

## 1. 프로젝트 개요

### Q1. 한 문장으로 설명해 보세요.

**[답변 예시]** "회사 업무를 기록하고, 근거로 확인한 성과만 남기고, 제출용 보고서로 출력하는 로컬 우선 도구입니다. 핵심은 문서 편집이 아니라 근거 없는 수치가 문서에 들어가지 못하게 하는 구조입니다."

### Q2. 왜 웹 서비스가 아니라 로컬 도구인가요?

**[사실]** 인증이 없고 기본 바인딩이 `127.0.0.1`, 데이터는 OS 사용자 디렉터리의 JSON(`0600`)에 저장된다.
AI 는 기본 차단이며 설정에서 동의해야만 외부로 나간다.

**[답변 예시]** "회사 업무 기록은 민감하고, 개인이 통제할 수 있어야 한다고 봤습니다. 서버·계정 없이도 동작하고, 외부 전송은 명시적 동의 뒤에만 일어나도록 했습니다."

### Q3. 주요 사용자는 누구인가요?

**[답변 예시]** "성과평가·승진·이직 서류를 준비하는 회사 개발자입니다. 특히 팀 성과와 개인 기여를 구분해서 써야 하는 실무자입니다."

## 2. 데이터 모델·아키텍처

### Q4. 기록과 성과를 왜 나눴나요?

**[사실]** `Activity`(사실) / `Achievement`(해석) / `AIAnalysis`(제안)가 별도 모델·컬렉션이다.
AI 결과는 원본을 덮어쓰지 않고, 사용자가 적용해야 성과가 된다.

**[답변 예시]** "평가 시즌의 문제는 기록 부재와 근거 없는 해석이 섞여 있다는 점입니다. 원본을 불변으로 두면 AI 실패·재분석·수동 수정이 서로를 훼손하지 않습니다."

### Q5. CLI와 웹이 같은 규칙을 쓰는지 어떻게 보장하나요?

**[사실]** 두 진입점 모두 `ImpactService` 만 호출한다. 상태 계산·수치 검증·기간 집계가 서비스 계층에 있고,
API 는 얇은 변환 계층이다. 같은 시나리오를 API 테스트로 고정한다.

### Q6. 저장소로 JSON을 쓴 이유와 한계는?

**[사실]** 컬렉션별 JSON, 임시 파일 + `os.replace` 원자적 쓰기, 권한 `0600`.
한계는 프로세스 내 락만 있어 다중 워커·다중 사용자로 확장하려면 저장소 교체가 필요하다.

**[답변 예시]** "초기 제품은 설치·계정 없이 동작하는 것이 우선이었습니다. 대신 원자적 쓰기와 권한으로 손상·노출 위험을 줄였고, 확장 시 교체 지점을 `JsonStore` 하나로 모았습니다."

### Q7. 왜 기존 DevFolio를 지우지 않았나요?

**[사실]** `devfolio/` 는 YAML 저장소·CLI·API·내보내기 엔진·AI 신뢰성 계층을 제공하고,
레거시 테스트 401개가 회귀 안전망으로 남아 있다. 데이터는 읽기 전용으로 마이그레이션한다.

**[답변 예시]** "전면 재작성은 사용자 데이터와 검증된 AI·문서 자산을 버리는 선택이었습니다. 새 제품을 별도 패키지로 두고, 레거시는 호환 계층으로 유지했습니다."

## 3. 가드레일·AI

### Q8. AI가 만든 숫자를 어떻게 막나요?

**[사실]** `metrics.py` 가 숫자+단위 주장을 추출해 기록·근거·지표의 숫자와 대조하고,
불일치하면 `[확인 필요]` 로 치환한다. 보고서 본문에는 `Metric.verified` 만 들어가고,
나머지는 "확인 필요 항목" 부록에 모인다.

**[답변 예시]** "프롬프트로 '숫자를 만들지 마세요'라고 하는 건 확률적입니다. 모델 출력 이후에 결정론적으로 대조하고 치환하는 계층을 두었습니다."

### Q9. AI 실패는 어떻게 처리하나요?

**[사실]** `AIService._call` 실패 시 `AIAnalysis(status="failed", error_code=...)` 만 저장하고
Activity 는 변경하지 않는다. 실패한 분석은 적용할 수 없다(400). 재시도·모델 차단은 기존
`ai_reliability` 계층을 재사용한다.

### Q10. AI 동의는 어떻게 강제하나요?

**[사실]** `Settings.external_ai_consent` 가 `False` 면 409 `EXTERNAL_AI_NOT_ALLOWED`.
`allowed_providers` 가 있으면 해당 Provider 만 사용한다. 기본값은 차단이다.

### Q11. AI/Git 후보가 바로 성과로 확정되지 않게 한 이유는?

**[사실]** `source ∈ {ai, git}` 이고 `confirmed=false` 이면 상태를 항상 `needs_review` 로 둔다.
근거가 verified 여도 마찬가지다. 사용자가 체크해야 상태 계산이 정상화된다.

**[답변 예시]** "자동 수집은 후보를 빨리 만들지만, 해석의 책임은 사람에게 있어야 합니다. 확인 전에는 '근거 확인됨'으로 올라가지 않게 했습니다."

## 4. 문제 해결·디버깅

### Q12. 최근에 고친 버그를 설명해 보세요.

**[답변 예시]** "브라우저에서 기록 저장이 `form.get is not a function` 으로 실패했습니다. 테스트는 API만 호출해 이 경로를 보지 않았습니다. 폼 핸들러가 `FormData` 대신 form 요소를 헬퍼에 넘기고 있었고, 호출부를 고친 뒤 브라우저에서 저장·목록 반영까지 확인했습니다."

### Q13. Docker에서만 실패하는 문제를 어떻게 찾았나요?

**[답변 예시]** "마이그레이션이 컨테이너에서 0건이었습니다. 원인은 레거시 경로를 `IMPACTNOTE_LEGACY_DATA_DIR` 이 아니라 기본 경로에서만 읽던 것이었습니다. 레거시 경로 우선으로 고치고, 임시 레거시 데이터로 1회차 변환·2회차 멱등·원본 해시 불변까지 확인했습니다."

### Q14. "테스트가 통과한다" 외에 무엇을 확인했나요?

**[사실]** ruff·format·`node --check`, Docker 빌드·기동, `/api/health`, 컨테이너 내부 E2E,
마이그레이션 2회 실행, 브라우저 기록→성과→보고서 흐름을 확인했다.
PDF 실출력·실제 LLM 호출·스크린리더는 하지 않았고, 그렇게 보고했다.

## 5. 품질·테스트

### Q15. 새 기능을 어떻게 테스트했나요?

**[사실]** `tests/test_impactnote.py` 30개. 기록 CRUD, 성과·근거 상태, 지표 검증,
AI 동의/실패/수치 세탁(모의 호출), Git 후보, 기간 집계, 템플릿·버전·다운로드,
마이그레이션 멱등·백업·원본 보존, 브랜드·health/meta, 파일 권한을 고정한다.

### Q16. 테스트가 실제로 막는지 어떻게 확인하나요?

**[답변 예시]** "가드레일은 '허용되는 경우'와 '막히는 경우'를 함께 넣었습니다. 예를 들어 수치 테스트는 기록에 있는 값은 유지되고, 없는 값은 `[확인 필요]` 로 바뀌는 것을 같이 확인합니다. 마이그레이션은 원본 해시까지 비교합니다."

## 6. 트레이드오프·한계

### Q17. 이 설계의 가장 큰 비용은?

**[답변 예시]** "마찰입니다. 지표 값이 기록에 없으면 사용자가 입력해도 확인되지 않고, 후보는 한 번 더 확인해야 합니다. 대신 제출 문서에 근거 없는 숫자가 들어가지 않는다는 신뢰를 얻습니다. 이 마찰을 줄이는 UX가 다음 과제입니다."
