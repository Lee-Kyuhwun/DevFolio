# 에이전트 실수 기록부와 회귀 테스트 — 설계

- 상태: 설계 검토 중
- 작성: 2026-10-03
- 관련: [AI 협업 방식](../../ai-collaboration.md)

## 1. 배경

- 실제 모델에 연결해 실행하면서 사람이 찾은 장애를 여러 번 고쳤다(quota 0, 404, 비정형 JSON, 외국 문자 혼입, 빈 응답). 그런데 테스트로 고정한 것은 하나도 없다. 에이전트가 같은 코드를 다시 고치다 같은 실수를 해도 막을 장치가 없다.
- 2026-10-03 점검에서는 검증 장치 자체가 작동하지 않았다는 사실을 발견했다(CI 76회 연속 실패, pre-commit 미설치, 훅 미차단).
- AI 호출 로그(`ai_logs.jsonl`)는 최근 500건만 보관하고 응답도 400자 미리보기만 남긴다. 4월 장애 시점의 로그는 이미 없다. 그래서 기록의 근거는 **git 커밋 이력**으로 한다.

## 2. 목표와 비목표

목표
1. 장애마다 원인과 **기존 장치가 왜 못 막았는지**를 같은 형식으로 기록한다.
2. 장애마다 회귀 테스트를 하나 이상 둔다. 같은 실수가 다시 들어오면 `scripts/check.sh`에서 막힌다.
3. 회귀 테스트가 실제로 그 실수를 잡는지 확인한다. 조치를 일시적으로 되돌리면 테스트가 실패해야 한다.
4. 앞으로 장애를 고치는 에이전트가 같은 형식으로 기록하도록 규칙화한다.

비목표
- 로그 보관 정책 변경
- 실제 API 응답을 녹화해 재생하는 인프라. 짧은 수작업 fixture로 충분하다.

## 3. 산출물

| 파일 | 내용 |

## 4. 기록 형식

```markdown
### INC-NN 제목

| 항목 | 내용 |
|---|---|
| 날짜 | YYYY-MM-DD |
| 발견 | 사람(실제 모델 실행) / CI / 점검 / 에이전트 |
| 증상 | 사용자가 본 현상 |
| 원인 | 코드 수준 원인 |
| 기존 장치가 못 막은 이유 | 테스트·린트·심사가 왜 통과시켰나 |
| 조치 | 무엇을 바꿨나 (커밋) |
| 회귀 테스트 | 테스트 이름, 조치를 되돌렸을 때 실패하는지 확인 여부 |
```

"기존 장치가 못 막은 이유" 항목이 이 기록부의 핵심이다. 이 항목이 쌓이면 사람이 맡아야 하는 검증의 범위가 드러난다.

## 6. 회귀 테스트 설계

- **AI 호출 대체**: 기존 `tests/test_ai_service.py` 방식대로 `patch.dict("sys.modules", {"litellm": fake})`로 litellm을 대체한다. 실제 API는 호출하지 않는다.
- **fixture**: 각 테스트 안에 장애 응답을 본뜬 짧은 상수 문자열로 둔다. 별도 fixture 파일은 만들지 않는다.
- **이름 규칙**: `test_inc01_quota_zero_fails_without_retry`처럼 기록부 ID로 시작한다. 기록부와 테스트를 양방향으로 찾을 수 있다.
- **INC-06**: `pkgutil.walk_packages`로 `devfolio` 하위 모듈을 모두 import한다. 테스트가 import하지 않는 모듈의 문법 오류도 잡는다. 선택 의존성(weasyprint 등) 때문에 실패하는 모듈은 명시적 예외 목록으로 관리한다.
- **실제로 잡는지 확인**: 테스트마다 해당 조치 코드를 일시적으로 되돌려 테스트가 실패하는지 확인하고, 결과를 기록부에 "되돌림 확인: 실패함 ✅"으로 남긴다. 확인한 뒤 원상 복구한다.
- **작성 중 새 결함을 발견하면**: 현재 코드에서 테스트가 실패하면 그것 자체가 새 발견이다. 코드를 고치고 기록부에 "회귀 테스트 작성 중 발견"으로 기록한다.

## 7. INC-07을 자동 테스트로 만들지 않는 이유

git 훅이 막는지를 pytest 안에서 검증하려면 임시 저장소, pre-commit 환경 설치, 네트워크가 필요하다. 테스트가 느려지고 쉽게 깨진다.
대신 2026-10-03에 수행한 실험 A~E의 재현 절차를 기록부에 남긴다. 훅이나 `scripts/check.sh`를 바꿀 때 사람이 다시 수행한다.

## 8. 규칙 추가 (`AGENTS.md`, `CLAUDE.md`)

> 실서비스 장애나 에이전트 실수를 고치면 같은 커밋에서 `docs/agent-incidents.md`에 항목을 추가하고, `test_incNN_` 회귀 테스트를 추가한다. "기존 장치가 못 막은 이유"를 반드시 채운다.

## 9. 역할 분담

| 일 | 담당 |
|---|---|
| 장애 발견 (실제 모델 실행) | 사람 |
| 기록부 초안 (git diff 분석) | AI |
| "원인"과 "못 막은 이유" 최종 확인 | 사람 |
| 회귀 테스트 구현과 되돌림 확인 | AI |
| 규칙 승인 | 사람 |

## 10. 성공 기준

- 기록부에 8개 항목이 있고, 각 항목에 커밋과 테스트가 연결돼 있다.
- INC-07을 제외한 회귀 테스트가 통과한다.
- 각 테스트는 조치를 되돌렸을 때 실패한다(기록부에 결과 표기).
- `scripts/check.sh`와 CI가 통과한다.
