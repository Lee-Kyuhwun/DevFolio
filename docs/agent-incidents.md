# 장애·에이전트 실수 기록부

실서비스에서 드러난 장애와 에이전트 작업 중 생긴 실수를 기록한다.
핵심 항목은 **"기존 장치가 못 막은 이유"**다. 이 항목이 쌓이면 사람이 맡아야 하는 검증의 범위가 드러난다.

## 기록 규칙

- 장애나 실수를 고치면 **같은 커밋에서** 이 문서에 항목을 추가하고 회귀 테스트를 넣는다.
- 회귀 테스트 이름은 `test_incNN_*`로 시작한다(`tests/test_incident_regressions.py`). 이 문서의 ID와 1:1로 대응한다.
- 회귀 테스트는 **조치를 일시적으로 되돌렸을 때 실패하는지** 확인하고 결과를 적는다. 그래야 비어 있는 테스트가 아니라는 것을 알 수 있다.
- 커밋이나 기록으로 뒷받침되지 않는 내용은 "확인 필요"로 둔다.
- 4월 장애 당시의 AI 호출 로그는 남아 있지 않다(최근 500건만 보관). 그래서 INC-01 ~ 05의 근거는 git 커밋이다.

### INC-01 무료 등급 quota 0에서 재시도 반복

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-04-18 |
| 발견 | 실제 Gemini 응답에서 드러남. 누가 어떤 경로로 발견했는지는 확인 필요 |
| 증상 | 할당량이 0인 무료 등급에서 rate limit로 오인해 재시도만 반복했다 |
| 원인 | `limit: 0` / `free_tier_requests` 오류를 일반 rate limit와 구분하지 않았다 |
| 기존 장치가 못 막은 이유 | 이 오류 문구를 흉내 낸 테스트가 없었다. 모킹 테스트는 일반 rate limit와 인증 오류만 다뤘다 |
| 조치 | `limit: 0`이면 재시도 없이 결제 등록 안내와 함께 즉시 실패 (`2063cf6`) |
| 회귀 테스트 | `test_inc01_quota_zero_fails_without_retry`. 되돌림 확인: 실패함 ✅ (재시도해서 2회 호출) |

### INC-06 스마트 따옴표 문법 오류가 main에 반영

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-04-26 (커밋 `0ba5137`), 2026-10-03 발견 |
| 발견 | 2026-10-03 점검 중 Claude Code가 CI 기록과 HEAD를 확인하다 발견 |
| 증상 | `0ba5137`에서 `ai_service.py`의 스마트 따옴표(`“ ”`)가 5줄(주석)에서 60줄로 늘었고, 코드 부분(807행 타입 힌트 등)에 들어가 SyntaxError. 테스트 3개 파일 수집 불가. 앞선 `f7baf34`는 주석에만 있어 파싱은 정상이었다 |
| 원인 | 코드에 타이포그래피 따옴표가 섞였다. 어느 도구에서 들어왔는지는 확인 필요 |
| 기존 장치가 못 막은 이유 | Claude Code 훅을 거치지 않은 경로로 커밋된 것으로 추정(수집 오류는 pytest 종료 코드 2라 훅이 막았을 것). pre-commit은 미설치. CI는 실패했지만 이미 계속 실패하던 상태라 신호가 되지 못했다 |
| 조치 | 따옴표 수정 (`76bb520`). 커밋 전 검증을 git 훅으로 옮김 (`2452b7a`) |
| 회귀 테스트 | `test_inc06_every_devfolio_module_imports`: 테스트가 import하지 않는 모듈까지 모두 import. 선택 의존성(fastapi 등)이 없어서 생긴 import 실패는 건너뛴다(`test_inc06_missing_optional_dependency_is_skipped_not_failed`). 확인 방법: 조치를 되돌리는 대신 `devfolio/web/main.py`에 스마트 따옴표 문법 오류를 넣으면 실패함 ✅ |

| 조치 | `scripts/check.sh`를 git pre-commit과 Claude Code 훅이 함께 사용, 실패 시 종료 코드 2 (`2452b7a`). CI 첫 통과 (run `37106604049`) |

재현 절차 (훅이나 `scripts/check.sh`를 바꿀 때마다 수행):

| 실험 | 방법 | 기대 |
|---|---|---|
| A | `assert 1 == 2` 테스트를 추가하고 `git commit` | pre-commit `devfolio check` 실패, HEAD 그대로 |
| B | `X = “broken”` 파일을 추가하고 `git commit` | ruff `invalid-syntax`로 실패 |
| C | 실패 상태에서 Claude Code 훅 명령에 `{"tool_input":{"command":"git commit --no-verify -m x"}}` 입력 | 종료 코드 2 |
| D | 같은 훅에 `{"tool_input":{"command":"ls"}}` 입력 | 종료 코드 0 |
| E | 정상 상태에서 C와 같은 입력 | 종료 코드 0 |

## 공통 패턴

- **INC-01 ~ 05**: 모킹 테스트가 가정하지 않은 실제 provider의 동작(오류 문구, 모델 종료, 형식 일탈, 언어 무시, 빈 응답)에서 나왔다.
- **INC-06 ~ 07**: 검증 장치가 있다고 믿었지만 실제로는 작동하지 않았다.
- **INC-08**: AI 심사 결과를 코드로 다시 검증하지 않았다.
